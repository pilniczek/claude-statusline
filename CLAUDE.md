# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file Claude Code `statusLine` script (`statusline.js`). No build, no dependencies, no tests, no `package.json`. Node.js runs the script directly; Claude Code invokes it on each interaction and pipes a JSON payload to stdin. The script writes a single ANSI-colored line to stdout.

## Running / previewing changes

There is no test suite. The canonical way to eyeball changes is `node ./preview.js` — it spawns `statusline.js` once per representative tier (green ≈ 30k, yellow ≈ 120k, red ≈ 170k, full 200k, overflow 500k) and prints them stacked so the bar/color logic and the overflow label are visible side by side. The child inherits the parent's stdout (and gets `FORCE_COLOR=1`) so the terminal always renders the ANSI colors — don't change that without checking how it affects color output when piped or captured.

For one-off payloads:

```powershell
'{"model":{"display_name":"Opus 4.7 (1M context)"},"context_window":{"total_input_tokens":120000},"workspace":{"project_dir":"C:/tmp/demo"}}' | node ./statusline.js
```

To see it live in Claude Code, point `~/.claude/settings.json` → `statusLine.command` at this script and start a new session.

## Releasing

The live status line runs from a separate clone of this repo, not from this working tree. "Release", "deploy", "ship", "publish" or "update the live status line" in this repo is an explicit request for all three steps:

1. Commit the pending changes here (skip if the tree is clean).
2. `git push` to `origin/master`.
3. In the configured clone, `git pull --ff-only`. Find the clone from the directory of the script in `statusLine.command` in `~/.claude/settings.json` (currently `~/.claude/statusline/`).

Run `node ./preview.js` before step 1. Stop and ask if the clone has local changes or is not on `master`, or if `--ff-only` refuses: never merge, reset or force there. Report the commit both sides end on. The clone serves the next refresh, so no restart is needed.

## Architecture notes

- **Input contract**: stdin JSON shape that matters — `model.display_name`, `context_window.{total_input_tokens,current_usage}`, `rate_limits.{five_hour,seven_day}.used_percentage`, `transcript_path`, `cost.{total_lines_added,total_lines_removed}`, `workspace.{project_dir,current_dir}`, `cwd`. `workspace.project_dir` also scopes the cost part's project figure. The script defensively handles any of these being absent.
- **`SMART_ZONE` (default 200_000 tokens) is decoupled from the model's real context window.** The bar shows usage scaled against this fixed zone, not against the model's `context_window_size`. This is intentional: at 1M-context, 15% of the real window is already a lot of context — the bar is meant to track a "you should care" budget, not the technical max. Touching the bar math means understanding this.
- **Bar colors are positional, not value-based.** Of the 10 cells, 0-4 are always green, 5-7 yellow, 8-9 red — a full bar shows all three colors. The current-percentage label takes the color of the highest filled cell. Don't refactor `cellColor` into "color the whole bar by current pct" without confirming — that's a deliberate design choice from the README.
- **The plan usage readout (`h50% w70%`) is colored by value, unlike the bar.** Each token takes green/yellow/red from its own percentage, rounded up (`93.01` shows `94%`, never understating usage), against `RATE_LIMIT_YELLOW_ABOVE` (50) and `RATE_LIMIT_RED_ABOVE` (90). `rate_limits` and each window can be absent (Claude Code drops a window once its `resets_at` passes); a missing window or non-numeric value renders uncolored `h-%` / `w-%`, so the part is always present.
- **Token source** (`usedTokens` in `statusline.js`): `total_input_tokens`, else the sum of `current_usage.{input_tokens,cache_creation_input_tokens,cache_read_input_tokens}`. Output tokens never count, same as Claude Code's own `used_percentage`. `total_input_tokens` is `0` before the first API response, a real value, not a missing one. Never derive tokens from `used_percentage`: it is a percentage of the real window, shown as a whole number in the docs example, so on a 1M window each 1% step is 10k tokens. No token source shows an empty gray bar with `  -%`, so the line keeps its width.
- **The 🧠 and 📋 badges read files, not stdin.** `🧠 N` counts the claude-reflect queue, `learnings-queue.json` next to `transcript_path`, where claude-reflect keeps it per project; a missing queue is `0`, shown, not hidden. `📋` reads `WORK-REPORT.md` at the repo root (first ancestor of `workspace.current_dir` with a `.git` directory or file - no `git` process per render) and counts `- [` lines under `## Follow-ups`. States: `📋 N`, `📋✅` (zero), `📋 ✕` (no report and `cost` shows lines changed this session), `📋 -` (no report and nothing changed, or no repo). Counts and `-`/`✕` pad to `COUNT_DIGITS` (2) and `✅` is two cells wide, so every state has the same width; `🧠` pads the same way. Who wrote the report is deliberately ignored. Both files get the caveman flag's untrusted-file rules via `readSafeFile`: no symlinks, size caps, counts only, every failure hides the badge.
- **The cost part (`$6.84   📁 $0.55`) reads transcripts, not stdin.** `readTodayCost` walks `$CLAUDE_CONFIG_DIR/projects/**/*.jsonl` changed since local midnight, keeps records timestamped today, prices them from `CLAUDE_RATES` (rates and family fallback copied from the Claude Code Usage extension's `pricing.js`), and dedupes with the extension's rule in `dedupeEntries`: `message.id` + `requestId`, a missing `requestId` borrowed when the message has exactly one, no `message.id` keyed by `requestId` or by line, largest token sum wins. Stdin `cost.total_cost_usd` is session-only, so it can't give either figure. The project figure uses a path-boundary match on `cwd` (`isUnder`), stricter than the extension's plain `startsWith`; keep it. Any error hides the part. `$CLAUDE_CONFIG_DIR/statusline-cost-cache.json` holds the day key and, per transcript, size, parsed byte offset, its cwds once and its entries reduced per `(message.id, requestId)` pair (safe: the global dedupe keeps the same maximum), so a render parses only complete new lines and skips both read and write when no file changed; a shrunk file is parsed again from 0. A transcript deleted mid-scan is skipped, not treated as a missing `projects` dir. It is untrusted like the flag file: symlinks, files over `COST_CACHE_MAX_BYTES`, a wrong day or a bad entry shape all mean an empty cache, and writes go through a temp file + rename because several sessions render at once.
- **The caveman badge reads a flag file outside the session.** `readCavemanLevel()` reads `$CLAUDE_CONFIG_DIR/.caveman-active` (default `~/.claude/`), a flag file owned by the [caveman](https://github.com/juliusbrussee/caveman) plugin's hooks. Treat it as untrusted: the value is whitelisted against `CAVEMAN_LEVELS` and never printed raw, symlinks and files over `CAVEMAN_FLAG_MAX_BYTES` are refused, and every failure path returns `null` so a missing or hostile flag degrades to "no badge" instead of a broken status line. The whitelist and cap mirror the plugin's own `readFlag` in `caveman-config.js`.
- **The badge always names the level, including the `full` default** — `🦴 full`, never a bare `🦴`. It sits after the bar, just before the project name, so the bar keeps a fixed position whether or not caveman is active. This diverges from the plugin's own `caveman-statusline.sh`, which prints `[CAVEMAN]` for `full` and suffixes only other levels; the divergence is deliberate, since an unlabelled badge is indistinguishable from "some level, unnamed" and that is the blind spot the badge closes. Levels render verbatim and lowercase (matching the flag file and the `/caveman` argument) — no abbreviation of `wenyan-*`, and one-shot levels (`commit`/`review`/`compress`) show for their one turn rather than being resolved back through the plugin's `.caveman-active.prev`. `'off'` is whitelisted but unreachable in practice: every plugin deactivation path unlinks the flag instead of writing `off`.
- **Fixed width from 0% to 999%.** The bar label is left-padded to `PERCENT_DIGITS` (3) via `padPercent` (`  0%`). Two-value parts put all spare space between their values via `slack`, so each value keeps its symbol: `h6%  w94%` (`RATE_LIMIT_DIGITS`, 2, so `100%` adds one cell), `$15.30  📁 $7.62` (`COST_DIGITS`, 5). Without a project the cost pads after the total.
- **`│` separates groups, not parts.** `groups` in `statusline.js`: model + bar, cost, plan usage, badges (`🧠 📋 🦴`), project. Parts inside a group join with a space; an empty part or group drops out.
- **The project name (`📁 name`) is the last part**, so the bar's position no longer depends on how long the project name is.
- **Say *level*, not *mode*** — the flag holds one of `CAVEMAN_LEVELS`, and code, README, and comments all use "level" so the vocabulary can't drift apart again.
- All tunables (SMART_ZONE, BAR_WIDTH, BAR_YELLOW_ABOVE, BAR_RED_ABOVE, RATE_LIMIT_YELLOW_ABOVE, RATE_LIMIT_RED_ABOVE, PERCENT_DIGITS, RATE_LIMIT_DIGITS, COUNT_DIGITS, COST_DIGITS, PROJECT_ICON, SEPARATOR, COST_PROJECT_ICON, REFLECT_ICON, REPORT_ICON, REPORT_DONE_ICON, REPORT_MISSING_ICON, CAVEMAN_ICON, CAVEMAN_LEVELS) are constants at the top of `statusline.js` — README documents them as the configuration surface.
- **`preview.js` fixtures the reflect queue and work report** in per-row dirs under the same temp root; rows without them have no `current_dir`, so they show `📋 -` and never touch the real repo.
- **`preview.js` fixtures cost transcripts** under `projects/` in the row's config dir (`cost:` rows, expected `$4.00   📁 $2.00` and `$2.00   📁 $2.00`); every other row has none and shows `$0.00   📁 $0.00`.
- **`preview.js` fixtures the caveman flag.** Each scenario gets a throwaway `CLAUDE_CONFIG_DIR` under `os.tmpdir()` so badge and no-badge rows both render regardless of the level live on the machine. Don't let it fall back to inheriting the real config dir — that silently makes half the preview unreachable.
